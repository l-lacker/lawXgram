# Neogram AGENTS

Neogram is a **patchset** on top of Telegram for Android, not a fork. This repository holds
patches, Neogram's own code and tooling; `worktree/` is a generated upstream checkout with the
patches applied as one commit each. `patches/` and `series` are exports, never the source of truth.

## Layout
- `patchset.properties` — pinned upstream url/commit/version. Changed only by `patchset rebase`.
- `series`, `patches/<group>/<name>.patch` — generated by `patchset export`. Never edit by hand.
- `fork/java/ru/llacker/neogram/**` — Neogram Java code, compiled into `TMessagesProj`.
- `fork/res`, `fork/assets` — new resources only; overriding a stock resource goes to `fork/app/res`.
- `fork/app/**` — app-module code, manifest overlay and brand graphics.
- `fork/core/**` — pure Java logic with JUnit tests (no Android types).
- `fork/branding.properties` — the only place for the app name, application id and links.
- `tools/patchset.py` — the patchset tool (`patchset.cmd` / `patchset.sh`).
- `worktree/` (ignored) — upstream checkout; stock edits happen here. `local/` (ignored) — secrets.

## Commands
- Set up or refresh the worktree: `patchset setup` (`--force` rebuilds diverged commits).
- New patch from staged changes: `patchset new <group>/<name> -m "<ascii description>" [-a] [--body "..."]`.
- Fold changes into an existing patch: `patchset fixup <group>/<name> [-a]`.
- Reorder/rename/drop: `patchset move|rename|reword|drop|edit …`, then `patchset continue` if stopped.
- Export after every stack change: `patchset export`. Verify: `patchset export --check`, `patchset check --sparse`, `patchset lint`.
- Update upstream: `patchset rebase <commit|latest>`, resolve, `patchset continue`, review `changed` output.
- Tool tests: `python -m unittest discover -s tools/tests`. Core tests: `worktree/gradlew -p fork/core test`.
- Android build: `cd worktree && ./gradlew :TMessagesProj_App:assembleDebug --console=plain`
  (Windows: `gradlew.bat`; add `-Pneo.abis=arm64-v8a` for a fast single-ABI build).

## Patch rules
- Groups: `misc` (build, branding, infra), `hooks` (shared extension points, ≥3 consumers), `feature`,
  `debloat` (hide/disable stock behaviour, behind a setting), `bugfix` (one upstream fix per patch).
- Commit subject in the worktree: `<group>/<kebab-name>: <short ASCII description>`; details go to the body.
- Keep stock changes small: wiring, guards, short inline logic. Logic longer than ~7 lines goes to a
  helper in `fork/`. Every patch should be removable on its own.
- Replacing behaviour: a guarded early-return branch before the stock code. Extending: call fork code
  after the stock code. Never re-indent stock code inside a new `if`.
- Call fork code by fully-qualified name (`ru.llacker.neogram.…`), no imports in stock files.
- Prefer widening a private member to public over adding new API; new members of stock classes are
  prefixed `neo_`. Never change signatures of stock public methods — add an overload instead.
- No `true ||` / `false &&` toggles, reflection, hidden-API bypasses, commented-out stock code,
  hardcoded keys, binary diffs, or new files under `org/telegram/**` (fork code lives in `fork/`).
- Never edit `TLRPC.java`, the stock database schema or `LAST_DB_VERSION`; Neogram tables are `neo_*`
  and migrate through `NeoDatabase`.
- `catch (Throwable)` only around UI hooks, never on send or data paths.

## Code and resources
- Java 17, Telegram style: 4-space indent, same-line braces, minimal diffs.
- Settings: typed items in `NeoConfig` (snake_case keys, `exportable`, mandatory description), pages in
  the settings hub; stock `SharedSettings` stays the home for options it already has (round video V2,
  audio recorder V2).
- Strings: `fork/res/values/strings_neo.xml`, every key starts with `Neo` and must not collide with a stock
  key. The app name is never a literal in strings — pass `NeoBrand.appName()` as a format argument.
  `values-*/strings_neo.xml` are Crowdin-managed; no `<plurals>` (use `_one`/`_other` keys), no `@string/` refs.
- Read strings via `LocaleController.getString(R.string.NeoXxx)`.

## Commits
- Collect only the changes made in the current session into the commit; never include unrelated or
  pre-existing worktree changes.
- Commit messages in Russian lowercase, written like a developer: a meaningful subject describing the
  result (`добавлена поддержка …`, `исправлена работа …`), not a bare infinitive, plus a detailed body
  that explains what changed and why.
- Do not push unless the task asks for it.

## Boundaries
- Never commit or expose `local/`, `local.properties`, `google-services.json`, `sentry.properties`,
  keystores or other secrets. Secrets reach the build through `local/secrets.properties` or `NEO_*` env vars.
- Ask before changing the application id, signing, Firebase or Sentry wiring, ABI splits, APK naming,
  Play-specific permissions, the Gradle toolchain or major dependencies.
- Treat upstream vendor trees in the worktree as high-risk: `jni/third_party/**`, `jni/voip/**`,
  `TMessagesProj_Modules/media/**`, `org/webrtc/**`.
- Do not hand-edit generated files (`patches/`, `series`, build outputs).
